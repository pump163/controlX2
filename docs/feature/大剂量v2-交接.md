# 大剂量 v2 交接

> 只做索引与状态；设计正文见 `docs/feature/大剂量功能设计-v2.md`。最后更新：2026-11-06。

## 1. 已定决策

- **X2 不能远程发起延展**：`-98` 的延展三字段是 Mobi 语义，X2 固件忽略；X2 侧只给「请到泵本体操作」提示。
- **Mobi 走 11 参**：`bolusTypeBitmask = 12`（实测值，非唯一合法值），`extended3 = 0`；不要用库内 `BolusType#toBitmask` 推导。
- **时长单位**：wire 用秒，历史 `extendedDurationRequested` 用分钟。
- **`totalVolume` 是立即段**，不是整次总量；延后段在 `extendedVolume`。
- **预设存绝对值**（`immediateMilliunits` / `laterMilliunits` / `durationMinutes`），百分比只做派生显示，避免换算漂移。
- **三标签「大剂量 / 向导 / 预设」**：默认「大剂量」，未知来源 / 进程重建恢复失败也回「大剂量」。
- **草稿全局单例**：标签只记来源标量；已有 DRAFT 时复用同一对象，不新建第二份。
- **「上次大剂量」只做不可点击的提醒行**：不做入口、不做来源类型、不做预填、不带箭头。
  取值**保持现状**：最近一次 `LastBolusStatusV2` 的 `deliveredVolume` + `timestamp`（`DataStore.lastBolusStatusResponse`），**包含被取消或部分输注的量**，与首页卡片同源。
  用户理由：① 取消/部分也是实际发送到泵并执行过的命令，反映真实发生的事；② 读「完全执行完毕」的历史记录反而麻烦，取消是出错后的小概率特例；③ 提醒是提醒，不是强制拦截；④ 与首页同源，看到的始终是同一个数。
  不做入口的理由：入口等于「一键重复上次剂量」，容易被误当成快捷补药；提示只需拦一下手。
  强度：≤2 小时警示色 + 加粗，2–24 小时弱化，>24 小时不显示；文案为绝对时间（`shortTime`），不设刷新定时器。
- **取消节流 3 次 / 15 秒**：`CANCEL_THROTTLE_WINDOW_MS = 15_000`；另有一个 5 秒「停止兜底」，两者不是同一个窗口。
- **高度两档**（全屏 / 半屏，默认全屏）：键盘弹出时临时按全屏渲染，不改持久化档位。
- **能力 / 阈值只读** `assets/pump-capabilities.json`（经 `PumpCapabilities`），业务代码不写 `if (isX2)`。
- **X2 立即段最小值 50 mIU，Mobi 可为 0**（纯方波）；延展段 400 mIU 只是客户端兜底，不是泵下限。

## 6. 已知的坑

- **迁移百分比方向**：`percent` 是**立即段占比**；v1→v2 反算 `later = total * (100 - nowPercent) / 100`。
- **历史枚举 ≠ 请求掩码**：历史 `BolusType` 读数值 1/2/4/8/16（pumpx2 v1.9.0 枚举是旧映射）；请求侧 Mobi 直接写 12。
- **`-95 statusId=1`** 在库枚举之外，不要硬映射为成功 / 失败。
- **`46 / -74` 的 `duration` 单位未实证**：当前按秒读，需真机复核。
- **`maxExtendedSecondsNonCiq` 命名有误导**：它实际服务 CIQ+（V2，8h），不是「非 CIQ」。
- **`extended3` 必须恒 0**；`totalVolume` 只能放立即段。
- **取消节流 ≠ 停止兜底**：15 秒窗口与 5 秒兜底是两个常量，别合并。
- **切标签会中止 `-94` 等待**（`pendingPlan` 是 `remember`），但不会发生 `-98` 输注。
- **X2 `total=0` 纯方波会被拒**（`statusTypeId=1`）；Mobi 才接受 0。

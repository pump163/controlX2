# 大剂量 v2 交接

> 只做索引与状态；设计正文见 `docs/feature/大剂量功能设计-v2.md`。最后更新：2026-11-08。

## 1. 已定决策

- **X2 不能远程发起延展**：`-98` 的延展三字段是 Mobi 语义，X2 固件忽略；X2 侧只给「请到泵本体操作」提示。
- **Mobi 走 11 参**：`bolusTypeBitmask = 12`（实测值，非唯一合法值），`extended3 = 0`；不要用库内 `BolusType#toBitmask` 推导。
- **时长单位**：wire 用秒，历史 `extendedDurationRequested` 用分钟。
- **`totalVolume` 是立即段**，不是整次总量；延后段在 `extendedVolume`。
- **预设存绝对值**（`immediateMilliunits` / `laterMilliunits` / `durationMinutes`），百分比只做派生显示，避免换算漂移。
- **三标签「大剂量 / 向导 / 预设」**：默认「大剂量」，未知来源 / 进程重建恢复失败也回「大剂量」。
- **草稿全局单例**：标签只记来源标量；已有 DRAFT 时复用同一对象，不新建第二份。
- **「上次大剂量」只做不可点击的提醒行**：不做入口、不做来源类型、不做预填、不带箭头。
  取值**保持现状**：最近一次 `LastBolusStatusV2` 的 `deliveredVolume` + `timestamp`（`DataStore.lastBolusStatusResponse`），**包含被取消或部分输注的量**，与首页卡片同源。
  用户理由：① 取消/部分也是实际发送到泵并执行过的命令，反映真实发生的事；② 读「完全执行完毕」的历史记录反而麻烦，取消是出错后的小概率特例；③ 提醒是提醒，不是强制拦截；④ 与首页同源，看到的始终是同一个数。
  不做入口的理由：入口等于「一键重复上次剂量」，容易被误当成快捷补药；提示只需拦一下手。
  强度：≤2 小时警示色 + 加粗，2–24 小时弱化，>24 小时不显示；文案为绝对时间（`shortTime`），不设刷新定时器。
- **取消节流 3 次 / 15 秒**：`CANCEL_THROTTLE_WINDOW_MS = 15_000`；另有一个 5 秒「停止兜底」，两者不是同一个窗口。
- **高度两档**（全屏 / 半屏，默认全屏）：键盘弹出时临时按全屏渲染，不改持久化档位。
- **能力 / 阈值只读** `assets/pump-capabilities.json`（经 `PumpCapabilities`），业务代码不写 `if (isX2)`。
- **输注期不显示实时量**：`45` 无 `deliveredVolume`，只做「已开始 / 输注中 / 结束 / 未知」；发起后 0–10 s 确认、10 s 提示、60 s 归未知且不重试（明确拒绝立即结束）；输注中立即段每 10 s 查 `44`，延展段「连接对账 + 5 分钟兜底」（自然结束有泵侧主动 `47`；`45` 对延展恒零，不能判结束），间隔写进 `pump-capabilities.json`，横幅按 §4.9.4 生命周期、不秒级重绘。
- **`ACTIVE` 不区分立即 / 延展**：统一一个 `ACTIVE`，仅靠 `expectedEndAt` 是否存在区分形态（2026-11-07 定案，v2 §4.1 / §4.9.7 #57）。
- **X2 立即段最小值 50 mIU，Mobi 可为 0**（纯方波）；延展段 400 mIU 只是客户端兜底，不是泵下限。
- **向导输入跨标签保留**：状态在 `BolusWizardRuntime`，不在组合里；只有「清空」（X）/ 完成 / 成功发送才清。理由是算出的剂量需人工判断，返回核对原输入是流程前提。
- **`-98` 不上报碳水 / 血糖 / IOB**（默认 0，`wizard.report*ToPump = false`）：不留可追溯的医疗记录，开源软件不承担该责任。**该理由为可复用原则**：以后「这个数值要不要存」默认按此判。
- **向导血糖**：字段常驻，手动指血是主路径；CGM 有实时值预填且可改，不做 LastBG 回落；空 ≠ 0。内部只存 mg/dL 整数，mmol 按 18 换算、强制一位小数；换单位从 canonical 值重排，往返不走样。
- **血糖范围分两处**：手动指血 20–600 mg/dL（`wizard.fingerstick`）；CGM 预填按传感器型号（`wizard.cgmPrefill.bySensor`），未知型号取保守交集 40–400。全部在 `pump-capabilities.json`。
- **错误只陈述事实**：发现输入不对就判非法并保持，直到用户改对；不推测原因、不给建议。
- **计算器入口守卫**：进计算器前统一规范化（血糖整数 mg/dL、碳水整数克、剂量 mU）；血糖带小数则四舍五入（`roundToInt()` half-up）照常计算，只留一条不含医疗数值的诊断日志。
- **结果页竖排公式**：餐食 / 校正 / 已扣活性 / 建议四段，每段「标题 + 数值 + 小字算式」；界面只排版既有结果，**不重算**；缺项写「未填血糖，本笔不做校正」「未填碳水，本笔不计餐食」，空不是零。
- **IOB 取值顺序**：① 先真发一次 `ControlIQIOBRequest`，成功 → 用 `ControlIQIOBResponse` 的新值正常扣减；② 查询失败 / 超时才退回缓存，缓存 ≤ **3 分钟**（`wizard.iobStaleAfterMs = 180000`）可用，超过不予采信。
- **IOB 输注否决**：近 **5 分钟**（`wizard.recentInfusionVetoMillis = 300000`）有输注记录（本机发送 / 泵历史新增），或泵真相层正在输注 / **延展进行中**（`47`、`45` REQUESTING/DELIVERING）→ 不扣减。
- **两条文案分开**：A「活性胰岛素本次不可用，本次未扣除」；B「最近输注过大剂量，或有正在输注的大剂量，活性胰岛素可能不准确，本次未扣除」。
- **量级口径**：实测衰减 −0.09～−0.11 U/分钟 → 3 分钟约 **0.3 U**；要 ≤0.2 U 容差则窗口 ≤2 分钟。**不许把 5 分钟窗口写成 0.1 U 以下的偏差**。
- **来源与解耦**：IOB **不再**从 `BolusCalcDataSnapshotResponse.iob` 取；`BolusCalcDataSnapshotResponse` / `Message` 报文头都不带时间戳，时效只能按**本地到达时刻**判。
- **采样结论**：`/api/pump/current.iobUnits` 只跟 `ControlIQIOBResponse` 更新、断连整块冻结（实测 23.9 分钟，恢复后新值低 1.80 U）→ 问题在 App 侧缓存不标注时点，不在泵；3U 方波的 +1.00 U/5 min 台阶是泵自身记账粒度。
- **建议值可改**：改后结果页与确认页都显示 `建议 X / 实际 Y`；改写值必须符合泵步进与上下限，不合法停在结果页且不替用户取整。

## 6. 已知的坑

- **迁移百分比方向**：`percent` 是**立即段占比**；v1→v2 反算 `later = total * (100 - nowPercent) / 100`。
- **历史枚举 ≠ 请求掩码**：历史 `BolusType` 读数值 1/2/4/8/16（pumpx2 v1.9.0 枚举是旧映射）；请求侧 Mobi 直接写 12。
- **`-95 statusId=1`** 在库枚举之外，不要硬映射为成功 / 失败。
- **`46 / -74` 的 `duration` 单位未实证**：当前按秒读，需真机复核。
- **`maxExtendedSecondsNonCiq` 命名有误导**：它实际服务 CIQ+（V2，8h），不是「非 CIQ」。
- **`extended3` 必须恒 0**；`totalVolume` 只能放立即段。
- **取消节流 ≠ 停止兜底**：15 秒窗口与 5 秒兜底是两个常量，别合并。
- **切标签会中止 `-94` 等待**（`pendingPlan` 是 `remember`），但不会发生 `-98` 输注。
- **X2 `total=0` 纯方波会被拒**（`statusTypeId=1`）；Mobi 才接受 0。
- **不要在页面 / 协调器里自建单飞与节流**：那是查询器出口（`PumpCommandPort`）的职责。新增只读查询一律走端口，否则会与端口形成两套互不知情的在飞状态，超时重发会翻倍。
- **端口单飞键只按 opCode，不看 cargo**：`ActiveAamBitsRequest` 的 opCode 固定为 -110（146），cargo 是 1 字节的 2 或 4。`ALARM` 与 `MALFUNCTION` 同批到达时，`ActiveAamBits(2)` 与 `ActiveAamBits(4)` 会互相当成重复 → 第二条 `IN_FLIGHT`，真数据丢失。修法是把键改成「opCode + cargo 摘要」，需同步改 `inFlightSince` / `markThrottle` 的签名，**尚未修**。
- **事件补查不是「无条件全问」**：`onReceiveQualifyingEvent` 走的是 pumpx2 的 `suggestedHandlers` 最小集。看到某类 opCode 没发，先确认事件有没有带对应 bit，不要直接往页面加轮询。

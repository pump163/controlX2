## 0. 结论先行

1. 目标形态是**多窗口 TIR 汇总页**：五区间占比 + 覆盖率 + 均值/糖化 + AGP 分位带 + 逐日曲线 + 低血糖风险（LBGI / 事件频次）+ GRI。
2. **数据前提是条件式，不是无条件成立**：C 方案（本地数据库中的历史记录全量保留、不裁剪）+ 自动读取开启 + 首次追赶完成 + 未清空本地数据库。任一条件不成立，多日窗口就不完整；详见 §2.2。
3. 与现有内存机制不冲突：`InitialHistoryLogCount=5000` 只是首次追赶跨度（≈17 天 CGM）、`recentSeqIds=LruCache(256)` 只做流式去重、`itemLruCache=LruCache(500)` 只缓存解析结果。
4. 上游 TIR **只做了 24h**（最多 288 点、仅 70–180 单区间占比、无 TBR/TAR/GMI、无多天报表）；本地实现是补齐多窗口与多指标，不是换皮。是否回提上游由用户决定。
5. 本轮 docs-only：不编译、不出包、不碰 `D:\Programming\apk`。

## 3. 计算口径（实现前按此写单测）

> **单位声明**：本章所有阈值、分母、聚合与判定均以 **mg/dL 整数**计算；mmol/L 只在显示层换算一次（依据见 §4.6）。

### 3.1 输入与有效点

- 输入：`(timestampSec, bgMgdl, sourceType, pumpSid, seqId)`。
- 有效读数：`20 ≤ bg ≤ 600 mg/dL`（约 1.1–33.3 mmol/L）；超量程丢弃并计数到「无效点」。
- 去重：`(pumpSid, seqId)` 唯一；同 `pumpSid` 同 5 分钟槽位的多源读数只保留最新一条。
- 排序：按时间升序；同时间戳按 `seqId` 稳定排序。

### 3.2 时间加权（默认）

- **连续段**：相邻两点间隔 `≤ 15 min`（3 个采样周期）视为连续；`> 15 min` 断开。
- **单点代表时长**：
  - 段内点 `i`：`min(t[i+1] - t[i], 15 min)`；
  - 段内最后一点：`min(5 min, 段尾到窗口尾)`。
- **区间占比** = 该区间代表时长之和 / 有效覆盖时长（分母不含断流空洞）。
- **等权备选**只用于与截图「监测次数」对照，不作为 TIR 默认值。
- 断流阈值、单点封顶值放在常量里，便于后续调整（D2）。

### 3.3 覆盖率

- `覆盖率 = Σ 连续段代表时长 / 窗口墙钟时长`。
- 窗口时长按本地日历计算：普通日 86400 秒，DST 切换日 82800 / 90000 秒。
- 另示「监测次数 = 有效读数条数」；覆盖率与监测次数不可混为一个百分比。

### 3.4 按天分组

- 默认**手机本地日** 00:00–23:59:59.999；单日窗口=今天 00:00 至当前时刻，昨天=前一完整本地日。
- 7/14/30 天=含今天在内向前 N 个本地日（起于 N−1 天前 00:00，止于现在）。
- 自定义=起止日期均含当天整天。
- 每日本地日单独算 TIR / 覆盖率，再按「有效覆盖时长」加权汇总到窗口，避免长缺口日拉低整窗。

### 3.5 时区与 DST

- 展示与分组统一用手机本地时区；`pumpTimeSec` 仅作原始时间戳，换算用现有 `pumpTimeLocal()`。
- 手机时区变更后，页面重算；已导出报告不回溯。
- DST 当日覆盖率分母用实际秒数，不用固定 86400。

### 3.6 多源合并

- `CgmReadingHistoryLogs` 已含 FSL2 / FSL3 / 普通 CGM；同一 `pumpSid` 同一 5 分钟槽位只取最新一条。
- 不跨源平均、不跨 `pumpSid` 拼接；合并开关只改变「是否把多个泵的日数据并列展示并汇总」，不改变单点去重规则。
- 换传感器造成的数据重叠按槽位去重，重叠不重复计时。

### 3.7 多泵

- 默认按 `pumpSid` 分开：每个泵各自 TIR / 覆盖率，页面顶部可切换。
- 「合并」模式仅汇总展示，权重仍按有效覆盖时长；跨泵重叠时段只计一次（取时间较新者）。

### 3.8 聚合位置与性能

- 一次按时间窗查询窗口内 CGM 点（`HistoryLogDao.getItemsForTypesSince`），必要时按 5000 条分批；
- 聚合在内存完成，30 天约 8640 点，`O(n log n)` 排序 + `O(n)` 扫描；
- 目标：30 天首屏聚合 < 1s（真机验证项），页面切换窗口不重复全表扫描。

## 4. 阈值与单位（用户可配）

### 4.1 默认值（ADA 参考）

| 区间 | mg/dL（主值） | mmol/L（换算值） | 说明 |
|---|---|---|---|
| Very Low（二级低） | `< 54` | `< 3.0` | 严重低血糖 |
| Low（一级低） | `54 – 69` | `3.0 – 3.8` | 低血糖 |
| In Range（达标） | `70 – 180` | `3.9 – 10.0` | TIR |
| High（一级高） | `181 – 250` | `10.1 – 13.9` | 高血糖 |
| Very High（二级高） | `> 250` | `> 13.9` | 严重高血糖 |

> **mg/dL 是主值，mmol/L 是派生显示值**：边界来自整数 mg/dL（54、70、180、250），mmol 列只是按 18 近似换算后四舍五入的结果（70→3.9、69→3.8、180→10.0、250→13.9）。实现时不得把 3.9 当作独立边界，见 §4.6。

### 4.2 可改范围与规则

- 四个可编辑边界：`b1=54`、`b2=70`、`b3=180`、`b4=250`（**唯一真值是 mg/dL 整数**）。
- 校验：**严格单调递增**且相邻间隔 ≥ 10 mg/dL；建议范围 `b1 40–80`、`b2 60–120`、`b3 140–220`、`b4 200–350`。
- mmol 输入：界面允许按 mmol 输入，但先按 `GlucoseConverter.MGDL_TO_MMOL_FACTOR`（0.0555，≈1/18.018）反算并**四舍五入为整数 mg/dL 再落库**（如 3.9 → 70、13.9 → 250），绝不存 `3.89` 这类换算脏值；文档与代码均不得自造 18 / 18.016 常量。因显示只保留 1 位小数，`100 ↔ 5.6` 这类值允许 ±1 mg/dL 的回差（5.6 → 101），需要精确对齐指南整数时请用 mg/dL 模式。
- 非法输入：输入框即时标红、保存按钮禁用、恢复默认可用；不写入非法值。
- 单位切换：界面按设置单位显示（MGDL 整数 / MMOL 一位小数），**存储永远是 mg/dL**；切换只改显示，不改阈值。

### 4.3 修改后的行为

- 当前页**立即重算**（纯内存，阈值只是分桶边界），不重建数据库。
- 已导出的报告不回溯；导出的报告头标注阈值快照。
- GRI 使用当前五区间；若用户改阈值，GRI 数值仍计算，但需提示「GRI 系数基于 ADA 边界验证，自定义阈值下可比性下降」。

### 4.4 存储与作用范围

- DataStore pref：`tir-thresholds`，字符串 `"54,70,180,250"`（mg/dL 整数）；mmol 输入先按 §4.2 反算成整数再存；缺失或非法时回退默认。
- 全局生效（不按泵区分）；不进入 TM/文案 key（阈值是数值，不是文案）。
- 恢复默认入口放阈值设置页底部。

### 4.5 单位显示

- 内部计算一律 mg/dL；显示与输入换算一律走 `GlucoseConverter.MGDL_TO_MMOL_FACTOR`（0.0555，≈1/18.018），**文档与代码都不得出现自造 18 / 18.016 常量**。
- 阈值文案由同一组 mg/dL 常量派生：`70 ↔ 3.9`、`180 ↔ 10.0`、`54 ↔ 3.0`、`250 ↔ 13.9`，不写死两套字面量。
- 唯一例外是 LBGI：公式要求 mmol/L，只在函数内部转换（§9.2）；其余全链路 mg/dL，禁止「mg/dL → mmol → mg/dL」往返。

### 4.6 为什么内部用 mg/dL：阈值来源与单位策略

1. **阈值是美国指南按整数 mg/dL 定的**。ADA Standards of Care 等文件的 70 / 100 / 180 / 250 来自对美国人群正常血糖分布与并发症结局（DCCT 等）的统计，是**人群统计的近似线，不是生理常数**；个体长期处于高血糖时低血糖感知与报警阈值会随之上浮，所以指南线对个体并不总成立——这正是「内置参考值 + 用户可配」的理由。
2. **mmol/L 是派生值，不是设计值**。国内/国际惯例按 `1 mmol/L ≈ 18 mg/dL` 换算，于是才有 3.9 / 5.6 / 10.0 / 13.9 这类「看起来奇怪」的数字：3.9 只是 70÷18 的舍入结果，10.0 是 180÷18 的整除结果。把 3.9 当独立边界会在换单位时产生边界抖动。
3. **内部分层：mg/dL 是唯一真值**。存储（`tir-thresholds`）、计算（分桶、分母、TIR/GRI/LBGI、事件判定）全部用 mg/dL 整数；只在显示层按 `glucoseUnitPreference` 换算一次，禁止计算链中间转 mmol 再转回。
4. **与上游一致，不是另立一套**。Tandem X2 / Mobi 目前只在美加销售，泵侧口径本身就是 mg/dL；上游已有 `GlucoseUnit`、`GlucoseConverter`（`MGDL_TO_MMOL_FACTOR = 0.0555`，即 ≈1/18.018）与 `glucoseUnitPreference`，本方案直接复用。
5. **可配与 mmol 输入**。用户改的永远是 mg/dL 边界；mmol 模式下允许按 mmol 输入，但反算成整数 mg/dL 后落库（§4.2），避免出现 3.89 之类的非整数脏值；校验仍是整数、严格递增、最小间隔 ≥10 mg/dL。

| 用途 | mg/dL（主值） | mmol/L（换算，1 位小数） | 说明 |
|---|---|---|---|

### 4.7 人工录入血糖（指尖）的单位换算

**本项目调用现状：有依赖，但只用了非校准路径。** 生产代码在 `MainActivity :: sendServiceBolusRequest` 里以 `useForCgmCalibration = false` 发送；调试页 `Debug :: triggerRemoteBgEntryRequestMessage` 可手工把该位填 1，但只是裸消息、没有会话与前置校验；`LastBGRequest` 用于向导预填；会话启停由 `CGMActions` 负责。**没有校准 UI、没有校准状态机，也没有读取 `CgmCalibration*HistoryLog`。**

**若要做（另立项，不并入 TIR）的实现链**：

1. 前置读取：`CGMStatusRequest` / `CgmStatusV2Request` 确认会话活跃与传感器类型（G6/G7），并确认泵 API ≥ `API_V2_5`。
2. 组包：`RemoteBgEntryRequest(bgMgdl, useForCgmCalibration = true, entryType, source, pumpTime, bolusId)`；`pumpTime` / `bolusId` 的取值口径（泵运行秒数、是否允许 0 占位）**待核实**。
3. 发送并读 `RemoteBgEntryResponse.isSuccess`；区分「泵拒绝」「无会话」「超时」三态。
4. 事后核对：重新拉 history log，看 `BGHistoryLog.cgmCalibration != 0` 或 `CgmCalibration*HistoryLog` 是否新增。
5. UI 状态机：空闲 → 校验前置 → 待发送 → 等待回执 → 成功 / 失败（可重试）/ 超时；失败不得静默。

**不确定项（明确保留）**：泵固件是否真的把这条 BG 用于传感器校准算法、G6/G7/FSL 各类型的支持范围、`minApi = API_V2_5` 对应的泵型，均**未在真机验证**。history log 只能证明「泵记录了这次校准」，不能证明「传感器算法已采用」。

#### 4.7.3 录入链路（将来新增指尖录入 / 校准界面时按此实现）

1. **输入单位跟随设置**：`glucoseUnitPreference` 为 MGDL 时输入整数 mg/dL；为 MMOL 时输入 1 位小数 mmol。
2. **落库一律整数 mg/dL**，这是唯一真值；字段语义为「mg/dL 整数」，不存 mmol、不存输入字符串。
3. **mmol → mg/dL**：`Math.round(v / GlucoseConverter.MGDL_TO_MMOL_FACTOR)`，四舍五入到整数（3.9 → 70、5.6 → 101、13.9 → 250）。不得用 `.toInt()` 截断，也不得自造 18 / 18.016。
4. **回显**：`GlucoseConverter.format(mgdl, unit)`。mmol 只显示 1 位小数，因此 **100 ↔ 5.6 不是无损往返**（100 → 显示 5.6 → 再折算 101）。UI 必须说明「显示值可能与输入值差 0.1 mmol/L」，且**禁止为消除回差修改已存值**（例如看到 5.6 就把 101 改成 100）。
5. **单位切换只影响显示**：切换 `glucoseUnitPreference` 不回写、不迁移已有记录；同一条记录在两种单位下对应同一个 mg/dL 值。
6. **编辑已有记录**：
   - 按当前设置单位回显（`GlucoseConverter.format`）；
   - 保存时按当前单位重新折算成 mg/dL；
   - 若用户**没有改动输入文本**、且折算值与库中原值仅差 ±1 mg/dL（回差），**保留原值不覆盖**；
   - 判定方式：保存时同时比较「输入文本是否与回显文本一致」与「新折算值 vs 原库值」；两者都满足且差值 ≤ 1 才保留原值，否则以新折算值为准（用户确实改了数值）。
7. **不做往返链**：存储层不存 mmol，显示前不做「mg/dL → mmol → mg/dL」；一次换算只发生在「输入」与「显示」两个边界。

#### 4.7.4 校验与边界

| 项 | 规则 |
|---|---|
| 合理值域 | 20–600 mg/dL（1.1–33.3 mmol）；该范围是**提示线**，不是硬拦截（低于 20、高于 600 应允许记录但强提示） |
| 硬拒绝 | 空（= 未填，不等于 0）、0、负数、非数字 → 即时标红、禁用保存 |
| mmol 小数 | 允许 1 位小数；超过 1 位按四舍五入到 1 位再折算（或在输入层限制，二选一但须统一）；输入框不能用整数键盘 |
| 极端值 | < 20 mg/dL 或 > 600 mg/dL：二次确认 + 提示「可能填错单位」（典型误输：把 5.6 mmol 当 56 输入） |
| 上游校验 | `BolusCalcCondition.FailedSanityCheck` 只覆盖大剂量链路（`InitiateBolusRequest` 前）；指尖录入 / 校准的泵侧校验口径**待核实**，本地不另立医疗上限 |
| 非法输入与存量 | 校验失败不影响已存记录；也不因校验失败清空输入 |

#### 4.7.5 大剂量向导血糖框的既有缺陷（独立修复线，先记录不改代码）

1. **mmol 小数被整数键盘吞掉**：`IntegerOutlinedText` 只保留数字，输入「5.6」实际变成「56」，再按 mmol 折算 ≈1009 mg/dL；mmol 用户当前无法正常录入。
2. **截断而非四舍五入**：`GlucoseConverter.convert(...).toInt()` 对 5.6 得 100（100.9 被截断），与「四舍五入 101」不一致，正是 ±1 回差来源之一。
3. **小数 mmol 进不了换算分支**：`recalculate()` 先判 `rawToInt(输入) == null` 就返回 null，而 `rawToInt` 只认整数，导致「5.6」永远被当作未输入，`toDoubleOrNull` 那条换算分支成了死代码。
4. **空值被当成 0**：`rawToInt("")` 返回 0，mg/dL 模式下清空输入会以 0 参与大剂量计算，而不是「未填」。
5. **副标题归因错误**：`glucoseHumanEntered = it.toIntOrNull()`，小数 mmol 输入时该值为 null，副标题显示 `BG` / `CGM` 而非 `Entered`。

以上 5 条是**大剂量向导血糖框**的独立修复线，不阻塞 TIR 与指尖录入/校准；本节只记录，避免后续复用该输入控件时再踩。

#### 4.7.6 与 TIR 的关系

- 指尖血糖**不进 TIR 分母**：TIR / TBR / TAR / 覆盖率只统计 CGM 有效点（§3），人工录入值不参与时间加权。
- 指尖血糖的用途：CGM 校准参考、低血糖事件核对（与 CGM 曲线对照）、人工补录展示；多日视图可作**独立标记点**叠加，但不改变任何百分比。
- 若将来要把指尖值纳入统计（如「指尖达标率」或与 CGM 的偏差统计），**单列 D22**，不在本方案默认范围内。

## 5. 时间维度与日历

### 5.1 快捷窗口

- 今天 / 昨天 / 7 天 / 14 天 / 30 天 + 自定义起止日期。
- **默认窗口：7 天**（与截图一致；今天太短看不出趋势，30 天首屏成本高）。可在 D1 调整为「上次使用」记忆。
- 「今天」「昨天」为单日视图：显示 24h 曲线 + TIR 条 + 覆盖率；**不显示 AGP**（AGP 需多日才有意义）。
- 7/14/30 为区间视图：AGP + 逐日曲线列表 + 汇总数字。

### 5.2 日期边界

- 统一使用手机本地时区；起止日期含首尾整天。
- 跨 DST 按实际秒数；跨时区旅行后按当前时区重算，已导出报告不回溯。
- 未来日期不可选；窗口结束时间不晚于当前时刻（今天窗口止于 now）。

### 5.3 数据不足

- 请求窗口早于本地最早一条历史记录时：顶部提示「实际覆盖 N 天 / 请求 M 天」。
- 无数据日：日历灰显，逐日曲线不画该日；汇总只用有效覆盖时长，不按请求天数做分母。
- 全部无数据：显示空态与「去设置开启自动读取历史记录」入口，不显示 0%。

### 5.4 日历高亮判定

- 某本地日「有数据」= 该日有效 CGM 读数 ≥ **24 条**（约 2 小时覆盖，≈8%）。
- 建议常量 `dayHasDataMinSamples = 24`，可按需调整；高亮只表达「有」，不表达「够」。
- 高亮样式：小圆点/日期底色（随主题，不用 xDrip 的红点图形资源）；同时标注该日覆盖率百分比（可选）。

## 8. GRI、AGP 与变异度

### 8.1 GRI（档 1，与五区间同屏）

- 公式（公开文献，Klonoff et al. 2022）：
  `GRI_raw = 3.0×VLow% + 2.4×Low% + 1.6×VHigh% + 0.8×High%`，`GRI = GRI_raw / 3`。
- 输入直接用当前五区间占比；不新增取数。
- 归一到 0–100，0 最好。
- 系数核对原始文献后才上线（§8.5 风险）；未核对前可先只显示 TIR，不显示 GRI。
- 自定义阈值下仍可计算，但界面提示可比性下降（§4.3）。
- GRI 网格（低血糖成分 × 高血糖成分）放档 3，不阻塞档 1。

### 8.2 阈值与文献

| 区间 | 边界（mg/dL） | 系数 |
|---|---|---|
| VLow | < 54 | 3.0 |
| Low | 54–69 | 2.4 |
| In Range | 70–180 | 0 |
| High | 181–250 | 0.8 |
| VHigh | > 250 | 1.6 |

### 8.3 与 LBGI 的关系

- LBGI 只看低血糖；GRI 同时看两头，是超集；两者并存、不互相替代。

### 8.4 AGP 分位带（档 2）

- 按一天内 30 分钟时段分桶（48 槽，可调），每槽取 10/25/50/75/90 分位。
- 分位实现：排序后取最近秩，不插值；槽内样本 < 5 条时不画该槽。
- 横轴本地午夜对齐；DST 日槽位映射按实际时长缩放。
- 逐日曲线按日期开关绘制；默认显示窗口内全部日期。

### 8.5 变异度（档 2）

- MBG = 有效点算术平均（mg/dL）；eHbA1c 用公开 DCCT 公式（`(avg+46.7)/28.7`，avg 为 mg/dL）。
- SD 用样本标准差；CV = SD / MBG。
- 中位数按有效点排序取中位；AGP 的 50% 线是时段中位，不是全天单一中位数，两者分开标注。

## 9. LBGI 与低血糖事件

### 9.1 低血糖事件定义（共识）

| 判据 | 要求 |
|---|---|
| 事件开始 | CGM `< 3.9 mmol/L`（70 mg/dL）持续 **≥ 15 min** |
| 事件结束 | CGM `≥ 3.9 mmol/L` 持续 **≥ 15 min** |
| 二次事件 | CGM `< 3.0 mmol/L`（54 mg/dL）持续 **≥ 120 min**，计为第二次 |
| 准确性前提 | 低血糖区间 CGM 准确性有限，需提示 |

### 9.2 LBGI（档 2）

公式（暂定，须核对原始文献后启用）：

```
Trans(BG) = 1.794 × { [ln(BG)]^1.026 − 1.861 }
Trans < 0 ：Risk = 10 × Trans²
Trans ≥ 0 ：Risk = 0
LBGI = Σ Risk / n
```

- `BG` 必须是 **mmol/L**；内部 mg/dL，只在 LBGI 函数内用 `GlucoseConverter.MGDL_TO_MMOL_FACTOR` 转换。
- 零点在 **≈112 mg/dL（约 6.2 mmol/L；公式零点约 6.25 mmol/L）**：LBGI 累计的是目标中位以下的加权风险，**并非只统计 <3.9 的低血糖**。
- 按读数**等权**平均（公式定义），与 TIR 的时间加权不同；页面需注明口径差异。
- 极值过滤：`<1.1` 或 `>33.3 mmol/L` 的读数剔除（待原始文献确认）。
- 分档：`<0.7 极低 / 0.7–1.1 低 / 1.1–2.5 中 / 2.5–5 高 / >5 极高`。

### 9.3 事件频次（档 2）

- 事件判定必须按时间序列遍历，不能用占比代替。
- 采样 5 分钟时，15 min ≈ 连续 3 条且相邻间隔 ≤ 5 min；断流 > 15 min 视为中断，前后不接续。
- 跨窗口边界：事件算在**开始时刻所在窗口**；开始早于窗口的事件不计（D8）。
- 展示口径「次/天」与「次/窗口」二选一（D8）。

### 9.4 与 GRI 的关系

- GRI 用五区间占比；事件频次是另一套逻辑，不可互换。

## 10. UI 结构与 i18n

### 10.1 页面区块

1. **顶部**：窗口快捷按钮（今天/昨天/7/14/30）+ 自定义日期 + 日历高亮。
2. **汇总卡**：TIR 条（五区间）+ 覆盖率 + 监测次数 + MBG/eHbA1c + GRI。
3. **AGP 卡**（区间视图）：三条分位带 + 图例 + 单位刻度。
4. **逐日曲线卡**：日期开关 + 全选 + 每日折线。
5. **风险卡**：LBGI 分档 + 低血糖事件频次（档 2）。
6. **底部**：数据来源、覆盖说明、阈值入口（可配）。

### 10.2 交互

- 点区间条 → 显示该区间时长/占比说明；
- 点日期 → 单日视图（24h 曲线，无 AGP）；
- 单位切换 → 全页刻度与阈值文案一起换；
- 阈值修改 → 当前页即时重算；
- 数据不足 → 顶部黄条提示与灰显日。

### 10.3 i18n key 预估（en + zh 两侧等量）

| 档 | 内容 | 约需 key |
|---|---|---|
| 档 1 | 窗口 6、区间 5、汇总 8、覆盖率 4、空态/不足 4 | 24–27 |
| 档 2 | AGP 4、逐日 4、风险 6、变异度 4 | 18–20 |
| 档 3 | 导出/对比 8–10 | 10 |
| 阈值设置 | 标题/边界/校验/恢复默认 10–12 | 12 |
| 合计 |  | **约 64–69** |

> 这是修正后的估算；早前「14–18 个」只覆盖了档 1 的骨架，不含阈值页与空态。

### 10.4 暗色与可访问性

- 沿用主题 `surface/onSurface`，不写死黑/白；
- 区间色需在暗色下可辨（对比度 ≥ 4.5:1）；
- 图表提供内容描述（区间名 + 百分比）。

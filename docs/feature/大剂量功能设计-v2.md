# 大剂量功能设计 v2（并行实现）

> **一句话定位**：在 pumppan 分支**不改造**上游大剂量窗口，另建一套平行实现（`BolusWindowRouter` 分派 + `com.pumppan.controlx2.bolus` 包），设置页加开关在 `legacy` / `v2` 之间切换，默认 `legacy`；目标是**对上游与未来合并的影响最小**。
> **日期**：2026-11-03　**状态**：讨论稿 · 已归档 · 待推进（本轮**未动任何代码**，未编译、未出包）
> **前置**：`docs/old/大剂量功能设计.md`（2026-09 定稿，历史版本，仅作取证与背景参考）

## §1 与旧文档的关系

旧稿的三段式（输入态 → 全屏执行态 → 流式日志）在结构上被推翻，改为「**线性分步 + 单页外壳**」。逐条对照：

| 旧稿结论 | v2 处置 | 原因 |
|---|---|---|
| 全屏流程页（`BolusFlow` 覆盖层）vs 多页跳转之争 | **已定：线性分步、单页外壳**（不新增 `BottomScaffoldState`，复用已展开的 BottomSheet 内分派；全屏降级为待验证备选） | 单页分步才可能做到「只改 `Landing` 2 行」；全屏需要新增状态 + 修 reset 白名单 |
| 执行态窗口停留、轮询 `CurrentBolusStatus` 至结束 | **作废：发完命令即销毁窗口**，后续靠常驻通知 + Dashboard 横幅 | 延展段可达数小时，占屏就无法再发普通大剂量（旧稿 L143-148 的诉求保留，承载方式改变） |
| 「CIQ 自动模式禁止扩展」 | **作废**：允许扩展，只把时长上限压到 2h（Mobi 为 8h） | 用户更正：原记忆来源是美敦力；Tandem 固件（Moonlight 7.4 起）即支持 |
| 三结局显示已输注剂量 | **作废**：结局三态（成功 / 取消 / 失败）**一律不显示剂量** | 2026-09-29 已决策，v2 沿用并写死 |
| 预设带 `successCount` / `lastUsedAt` / 「另存提示」 | **作废**：预设 = 纯预填器，不计数、不排序最近使用 | 预设目的是「少输几个字」，计数无产品意义 |
| 「官方 App / 第三方并发发起我们完全不知道」 | **作废**：泵连接需蓝牙 code，同一时刻只有一个 App 连着；泵本体发起的可读，失去的只是「发起前的输入过程」 | 见 §4 与缺口修正 |
| 5 个 `mutableStateOf<Boolean>` + 5 个 `AlertDialog` 并发可弹 | **作废**：改为单一 `BolusSessionController` 单一状态源 | 旧实现的结构性缺陷 |
| Dialog 承载执行态（`BolusDialogs`） | **legacy 分支保留原样，v2 完全不用** | 平行实现，不改上游 |
| `BolusDraft` 唯一契约 | **保留**（字段收敛为 `totalMilliunits / extendedEnabled / nowPercent / extendedSeconds`） | 输入与执行解耦的思路仍然正确 |
| 单位/缩放铁律（profile 原始值、协议 mg/dL） | **保留**，但 v2 阶段 1 不做向导，暂不涉及 | 做向导阶段再启用 |

## §4 状态机与实时性

### 4.1 三态判定

```kotlin
// 输入只有两个：pumpConnected、holder.session
fun isAnyBolusActive(now: Long): BolusActivity = when {
    !pumpConnected                                    -> Unknown
    holder.session == null                            -> Idle
    holder.session.isExpired(now)                     -> Idle
    now - holder.session.lastEvidenceAt > staleWindow -> Unknown
    else                                              -> Active
}
```

- `Unknown` **只由断连产生**（以及「已连接但会话证据断流」这一短暂窗口）；**不再**表示「可能有第三方 App 发起」。
- 会话痕迹过期 → 归 `Idle`（已知已结束，不该长期占屏显示 Unknown）。
- `staleWindow` = 10 分钟（2× 兜底间隔，见 #52）。

### 4.2 消息驱动

- 单点入口：`MainActivity :: handleMessage` 开头一行 `BolusSessionController.applyMessage(message)`；controller 内部按报文类型更新 holder（`BolusPermissionResponse` / `InitiateBolusResponse` / `CurrentBolusStatusResponse` / `CancelBolusResponse` / `LastBolusStatusAbstractResponse`）。
- **5 分钟兜底轮询**：无消息时定期发 `CurrentBolusStatusRequest`，防止会话长期停留在过期前的假 Active。
- 重连/冷启动**对账顺序四步**：`CurrentBolusStatus` → `ExtendedBolusStatus` → `LastBolusStatus` → 历史日志；对账完成前取消行保持只读。

### 4.3 断连期间 UI 契约

| 情形 | 取消行 | 形态 | 点击 |
|---|---|---|---|
| 已连接 + Active | 显示 | 可点（danger 色） | 发 `CancelBolusRequest(bolusId)` |
| 已连接 + 有痕迹但 id 未知 | 显示 | 可点 | 先查 `CurrentBolusStatus` 取 id；取不到则不发 |
| 断连 + 有痕迹 | 显示 | **只读** | 无动作，提示「未连接，无法发送取消」 |
| 断连 + 无痕迹 | 不显示 | — | — |
| 已连接 + 对账中 | 显示 | 只读，数秒 | 无动作 |

fail-fast：`pumpConnected == false` 时**不发送、不进入「取消中」UI**，且不得落到「取消失败」文案（那是「已发送但结果未知」的语义）。

副标题文案：Active → 「扩展输注中 · 剩余约 %s」；断连 → 「未连接，状态未知」；对账中 → 复用 `bolus_fetching_bolus_stat`。

## §5 预设

### 5.1 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Long PK | 自增 |
| `name` | String | 用户命名，chip 显示 |
| `totalMilliunits` | Int | 总量（毫单位，整数域） |
| `extendedEnabled` | Boolean | 普通 / 扩展分组依据 |
| `nowPercent` | Int | 0–100，立即段百分比（普通恒 100） |
| `extendedSeconds` | Int | 延展时长 |
| `createdAt` | Long | 排序键（升序） |

### 5.2 表结构与约束

- 表 `bolus_presets`，Room v1，**无索引、无 Migration**（新库）。
- 分组：`extendedEnabled=false` → 「普通」组；`true` → 「扩展」组。
- 上限：单组 ≤ 5、合计 ≤ 6（`BolusPresetDao :: countByGroup` + `BolusPresetStore :: canAdd(group)`）。
- 排序：`ORDER BY createdAt ASC`；**不按使用次数、不记最近使用**。

### 5.3 与流程的三个接触点

1. **chip 预填**（步骤 1 / 步骤 2）：只填草稿，不改流程，不跳过任何确认；超上限按 §2-11 裁剪 + 横幅。
2. **长按编辑**：重命名 / 用当前草稿覆盖 / 删除。
3. **「加入预设」**：只在步骤 3 确认步出现，保存的是「经过检验的最终配方」。

## §6 时长上限与阈值

### 6.1 `maxExtendedSeconds(ciqEnabled, model, apiVersion)`

| 型号 / 条件 | 上限 | 备注 |
|---|---|---|
| Mobi | 28800（8h） | 官方支持 8h |
| X2 + CIQ 开 | 7200（2h） | 自动模式下压缩 |
| X2 + CIQ 关 + `apiVersion >= API_V3_2` | 28800（8h） | Moonlight 7.4+ 起 |
| X2 + CIQ 关 + 旧 API | 7200（2h） | 保守 |
| 型号或 API 读不到 | 7200（2h） | fail-closed，取小值 |

`apiVersion` 来源：`PumpVersionResponse`（`armSwVer/mspSwVer`）→ `KnownApiVersion` 对照（v7.1/7.4→`V2_1`、7.6→`V2_5`、7.7→`V3_2`、7.8→`V3_4`；Mobi 7.6→`V3_5` 等）。**pumppan 全仓当前 0 引用，需新增读取**（待验证）。

### 6.2 超限三层处理

1. **手动输入** → 报错 + 「一键改到上限」，**不静默裁剪**。
2. **预设回填** → 裁剪到上限 + 可见横幅。
3. **泵侧** → 库无法表达「时长超限」拒绝（`InitiateBolusResponse :: BolusResponseStatus` 只有 `SUCCESS(0)` / `REVOKED_PRIORITY(2)`），所以**必须 App 先拦**。

### 6.3 百分比 → 毫单位换算表（half-up，余数归延时）

| 总量 | 50% / 50% | 70% / 30% | 0% / 100% |
|---|---|---|---|
| 0.40U（400） | 200 / 200 | 280 / 120 | **0 / 400**（恰为门槛等号） |
| 0.45U（450） | 225 / 225 | 315 / 135 | 0 / 450 |
| 0.50U（500） | 250 / 250 | 350 / 150 | 0 / 500 |
| 1.00U（1000） | 500 / 500 | 700 / 300 | 0 / 1000 |
| 3.50U（3500） | 1750 / 1750 | 2450 / 1050 | 0 / 3500 |

校验式（毫单位整数域）：`total >= 50 || (total + extended) >= 400`。
`nowPercent = 100` 必须归一化为 8 参普通路径；`nowPercent = 0` 且总量不足门槛时给出明确报错（文案见 §7）。

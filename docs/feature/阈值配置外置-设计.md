# 机型配置与协议差异（正本）

> **取代关系（2026-11-07）**：本文件由原《阈值配置外置-设计.md》改写，原稿以下内容**全部作废**，不得再作为口径：
> ① 文件名 `assets/pump_limits.json`；② 扁平 key + `models` / `firmware` / `ciq.enabled` 多层合并的 schema；③ `prefs` 运行时覆盖层与「七级优先级」；④ `-98` 应答看门狗 30 s、`staleWindow` 600 s 等阈值进配置的清单；⑤「仅设计、未实现」的定位。
> **现实**是：`mobile/src/main/assets/pump-capabilities.json` 已是唯一读取源，由 `PumpCapabilities` 解析，按 `commands / limits / ui / units / encodings` 分组，型号键为 `default` / `TSLIM_X2` / `MOBI`。
> 逐条协议差异与出处见 [协议差异清单-出处表.md](协议差异清单-出处表.md)。**JSON 内不写注释**，语义一律放在那张表里。

## §2 配置分两类

### 2.1 A 类：机型能力（能不能做）

| 能力 | `TSLIM_X2` | `MOBI` | `default` | JSON 键 | 依据 |
|---|---|---|---|---|---|
| 普通大剂量发起 | true | true | true | `commands.initiateNormalBolus` | 真机已验（X2 发送链路） |
| **远程发起延展** | **false** | **true（未真机验证）** | true | `commands.remoteExtendedBolusStart` | X2 忽略 `-98` 延展三字段（6851/6852）；Mobi 仅上游 501 抓包 |
| 延展状态只读 | true | true | true | `commands.extendedBolusStatusRead` | X2：`46/-74` 只读正常（6850） |
| 延展取消 | true | true | true | `commands.extendedBolusCancel` | X2：`-96` 取消 6850 成功 |
| `-16` 权限释放 | unverified | unverified | unverified | `commands.bolusPermissionRelease.status` | 2026-11-06 未发 `-16` |
| 输注步进 | 50 mU | 50 mU | 25 mU | `limits.bolusIncrementMilliunits` | X2 用户核实 0.05 U；Mobi 手册 §32.4（未真机） |
| **立即段最小** | **50 mU** | **0** | 50 mU | `limits.minImmediateMilliunits` | X2 `total=0` 被 `statusTypeId=1` 拒；Mobi 接受纯方波 |
| 延展最短 | 900 s（15 分钟，继承 `default`） | 900 s | 900 s | `limits.minExtendedSeconds` | 说明书 7.6；X2 块内未写该键，回落 `default` |
| 延展上限 CIQ 1.0 | 120 分钟（7200 s） | 120 分钟 | 120 分钟 | `limits.maxExtendedSecondsCiq` | H10 说明书 7.6 / 抓包 duration=7200 |
| 延展上限 CIQ+ 1.5 | 480 分钟（28800 s） | 480 分钟 | 480 分钟 | `limits.maxExtendedSecondsNonCiq` | Mobi 观测最大值（非协议上限） |

> **命名坑**：`maxExtendedSecondsNonCiq` 实际承载 **CIQ+ 1.5 的 8h**，不是「非 CIQ」；`maxExtendedSecondsCiq` 承载 CIQ 1.0 的 2h。
> **实现缺口**：`PumpCapabilities.maxExtendedSeconds(ciqEnabled)`（`PumpCapabilities.kt:59-60`）只按布尔取值——`controlIQEnabled=true` 一律取 7200，**CIQ+ 1.5 会被压到 2h**。偏保守、不会发出非法请求，但 UI 上限偏小。按版本分档属实现改动，本轮不动代码（见 §5）。

### 2.2 B 类：协议差异（怎么读、怎么写）

只列一句摘要，逐条依据见 [协议差异清单-出处表.md](协议差异清单-出处表.md)。

| 差异 | 落点 |
|---|---|
| X2 无 `-73`，只能认 `47` | 状态消费按响应类分派，不按 opcode 数字 |
| `47` 事件驱动、无周期推送，断连即错过 | 输注期必须主动轮询（见 §4 建议键） |
| 请求 / `47` 时长=**秒**，历史 `280.extendedDurationRequested`=**分钟** | `units.wireDuration` / `historyExtendedDurationRequested` |
| `bolusSource`：1=泵本体，8=本 App | 取证日志字段 |
| `-91`：`bolusStatusId` 3=完成、0=取消；`deliveredVolume` 单位 mU | `LastBolusStatusV3Response` |
| 取消与完成时 `47/45` 归零**同形** | 不能用归零判结局 |
| `45` 无 `deliveredVolume` | 不做实时量显示 |
| Mobi 延展请求 `bitmask=12`（实测） | `encodings.extendedBitmask` |
| 60 s 整包**不含** `46`；唯一发送点在 V2 对账，LEGACY 不查 | `BolusEntryCoordinator.kt:61` |

## §4 修改规则

1. **JSON 不写注释**：值只放数字 / 布尔 / 短字符串；语义、样本、置信度一律进 [协议差异清单-出处表.md](协议差异清单-出处表.md)。
2. **一值一出处**：新增或修改任何键，先补出处表（哪次抓流 / 哪份文档 / 哪段代码），再改 JSON。
3. **未验证不得写成结论**：用 `status` / `verified` / `unverified` 字段显式标注；`remoteExtendedBolusStart` 判定只看该布尔，不看 `verified`。
4. **型号识别不到走 `default`**：`default` 是兜底档（步进 25、允许远程延展），不要把它当 X2 使用。
5. **本轮不改 `pump-capabilities.json`**：以下为建议新增键，待实现时再落盘。

### 4.1 建议新增键（未落盘）

| 建议键 | 值 | 用途 | 来源 |
|---|---|---|---|
| `limits.immediatePollIntervalMs` | 10000 | 立即大剂量输注期轮询间隔 | 大剂量功能设计 v2 §4.9.3（2026-11-07 定案） |
| `limits.extendedPollIntervalMs` | 300000 | 延展段兜底轮询间隔（连接时另对账一次） | 同上（2026-11-07 晚实测自然结束有主动 `47`，由 60 s 降级为 5 分钟） |
| `protocol.extendedStatusResponseOpcode` | `47` | 显式声明 X2 只认 `47`，避免误用 `-73` | 本文 §2.2 / 出处表 D1 |
| `protocol.bolusSourceApp` | `8` | 区分本 App 发起（1=泵本体） | 出处表 D4 |

> 轮询间隔放 `limits` 还是新开 `protocol` 组尚未定；两者都只是文档建议，**本轮不动 JSON**。

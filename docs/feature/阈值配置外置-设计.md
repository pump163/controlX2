# 阈值配置外置（设计稿）

> 状态：**仅设计，未实现**。目标是把「随固件/型号变化的阈值」从代码常量挪到可替换的数据文件，减少改常量就要编译的次数。本轮只写方案，不建源码、不改 `:shared`/pumpx2。

## §1 为什么要外置

- 型号与固件会变（X2 / Mobi、7.6 / 7.7 / 7.8…），剂量边界、扩展时长上限、状态计时等常量会跟着变。
- 写死在 Kotlin 里，每变一次要改代码、重编译、重出包。
- 但 Android 的硬事实：**只要值随包发布（assets），改它仍然要重新打包和重新签名**；真正「不重打包就能改」只能靠运行时覆盖层（prefs / DataStore）。因此本方案按「出厂默认在 assets、现场覆盖在 prefs」设计。

### 2.2 不进文件

| 项 | 原因 |
|---|---|
| 当前 Max Bolus / 当前 Max Basal / CIQ 开关 / 固件版本 / 电量 / 储药量 | 必须实时读泵（`GlobalMaxBolusSettingsResponse`、`BasalLimitSettingsResponse`、`ControlIQInfoResponse` 等），写进文件等于伪造「当前值」 |
| TIR 目标范围、低/高阈值 | 属 TIR 自己的配置与文档（`TIR多日汇总-远期目标.md` §4），不混入大剂量阈值 |
| opCode、字段布局、`minApi`、11 参结构 | 属 pumpx2/协议，改错会直接发错命令 |
| 文案、单位、格式化 | 属 `strings.xml` |

## §3 落法比较

| 方案 | 优点 | 缺点 |
|---|---|---|
| ① `assets/pump_limits.json`（随包） | 结构清晰、可按型号/固件分档、无新依赖（`org.json` 内置） | **改文件仍需重新打包 + 重新签名**；不能热更；真机上用户改不了 |
| ② `SharedPreferences`/`DataStore` 覆盖层 | 运行时热更；调试页可导入/手改；不动签名 | 需自行校验与回退；易被误改；无版本概念 |
| ③ **assets 默认 + prefs 覆盖（推荐）** | 出厂默认可审阅、可随包版本化；调试期免重编；验证过的值可回写 assets | 多一层 merge（约 100 行） |

推荐 ③。明确写出：**纯 assets 方案并不能省掉「重新打包」**，它省的只是「改代码」；只有 ② 才能在不重打包的前提下改值。③ 让「调试期热更 → 回写出厂默认」形成闭环。

## §5 优先级与兜底

### 5.1 七级优先级（后者覆盖前者，逐 key 合并）

1. 代码内 `HardDefaults`（永远存在，不可被删）
2. `assets/pump_limits.json → default`
3. `models[当前型号]`（`determinePumpModel`）
4. `firmware[型号][固件版本]`（取不到就跳过）
5. `ciq.enabled`（仅 `controlIQEnabled == true` 时叠加）
6. `prefs` 覆盖层（调试页导入/手改，最高优先）
7. 运行时用泵上报的 `maxBolus` / `basalLimit` 修正**兜底值**（不覆盖剂量与时长常量）

### 5.2 硬边界钳制（文件不得放宽）

| 键 | 钳制范围 |
|---|---|
| `minBolusMilliunits` | 50–25000，且不得大于 `maxBolusMilliunits` |
| `maxBolusMilliunits` | 50–25000 |
| `extendedNowMinMilliunits` | 50–`maxBolusMilliunits` |
| `extendedMaxSeconds` | 300–28800 |
| `bolusResponseTimeoutSeconds` | 10–120 |
| `staleActiveWindowSeconds` | 60–3600 |
| `presetMaxTotal` | 1–12；运行时实际取 `min(presetMaxTotal, 单屏可容纳数)`，且 `presetSingleScreenOnly` 恒为 `true`（一屏不滚动） |

即文件可以把限制**收紧**（更保守），但不能突破代码内的绝对边界（突破需要改代码并重新评估）。

### 5.3 加载、校验与失败

- 读取时机：进程启动后首次使用时惰性加载一次（单例缓存）；prefs 覆盖变化时重读；Debug 页提供「重载阈值文件」入口（读 assets + prefs，清缓存）。
- 校验：类型、范围、单调性（`min <= max`）、时长 `> 0`；单 key 非法 → 该 key 回退上一级，`Timber.w` 一条。
- 整份解析失败（缺失/损坏/未知 `schemaVersion`）→ 全部回退 `HardDefaults`，`Timber.w` 一条，**不崩**。
- prefs 覆盖里出现未知 key → 忽略；出现非法值 → 该 key 忽略。

## §6 风险表

| 情形 | 处理 | 用户可见 |
|---|---|---|
| 文件缺失 | 用 `HardDefaults` | 无感 |
| 字段缺失 | 逐 key 回退 | 无感 |
| 值越界/类型错 | 单 key 拒收 + 钳制 | 可在调试页提示「N 项被忽略」 |
| 型号未匹配 | 跳过 `models`/`firmware` 层 | 无感 |
| 固件版本取不到 | 跳过 `firmware` 层 | 无感 |
| JSON 损坏 / 未知版本 | 整体回退 + 日志一条 | 无感 |
| prefs 覆盖误改 | 只影响被改 key；可「恢复默认」一键清除 | 调试页可见 |

## §7 实现边界

- 全部放在 `com.pumppan.controlx2.bolus.limits`：`PumpLimits.kt`（加载/合并/校验/钳制）、`PumpLimitsSchema.kt`（解析）、`PumpLimitsOverrides.kt`（prefs 覆盖）。
- 对外只暴露一个 `PumpLimits.current()`；消费点只有两处：`BolusForm` 的校验、`BolusSessionController` 的计时。
- **不侵入 `:shared` 与 pumpx2**：型号判断复用 `determinePumpModel`，CIQ 复用 `controlIQEnabled`，固件版本复用 `PumpVersionResponse`（只读）。
- 文件位置：`mobile/src/main/assets/pump_limits.json`（默认）；prefs 覆盖存在 `PumppanPrefs` 独立 key（JSON 字符串）。

## §2 Tandem 7.1–7.5 事实表（逐章）

### 2.1 §7.1 Bolus Helpers（p.80–81）

| 事实 | 内容 |
|---|---|
| 最小/最大大剂量 | 最小 **0.05 U**（p.80）；**Max Bolus 默认 10 U，可设 1–25 U**（§7.7 p.88） |
| 步进 | **0.05 U**（与用户核实的 X2 精度一致；Mobi 待核实） |
| 碳水开关 | `Carbs` 开 → 按克数输入；关 → 只能按单位输入（没有「按克数」入口） |
| 向导前置条件 | 必须已设置 Basal、Correction Factor、Carb Ratio、Target BG；**没有基础率时段时泵不计算校正大剂量**（§5.2 p.62） |
| 手动大剂量对 CIQ | CIQ 开启时，手动大剂量后 **60 分钟内暂停自动校正**（p.80） |

### 2.2 §7.2 Correction Bolus（p.81–83）——本章即「向导核心」

| 项 | 事实 |
|---|---|
| 输入项 | 当前 BG（可手输，或 CIQ 开启时用 CGM 当前值自动带出）、碳水（克数或单位，取决于入口） |
| 血糖来源 | **只有当前 CGM 值**；**不使用趋势箭头**做外推；CGM 自动带出要求：CIQ 开、CGM 会话活跃、有当前读数、有趋势箭头 |
| 可覆盖 | 用户可手动改 BG 值（覆盖自动带出的 CGM 值） |
| BG 高于目标 | 校正 = 高于目标的部分；**IOB 只从「校正」里扣，不扣食物部分** |
| BG 在 70 与目标之间 | 校正为 0；提示用户**可自行减少食物大剂量**；**IOB 也会用于减少总量** |
| BG 低于 70 | **自动减少食物大剂量**（按低血糖校正）；**IOB 也参与减少**；提示先补快速碳水 |
| BG 恰好等于目标 | 不弹 Above/Below 确认页 |
| 未输入 BG | 不做校正（等价于只算食物）——Tandem 未明写，按 Medtronic 公式 4 与操作流推断 |
| 计算后 | 显示总剂量并回到 Bolus 界面；可接受或修改 |

### 2.3 §7.3 Bolus Override（p.85）

| 项 | 事实 |
|---|---|
| 覆盖入口 | 始终可用（正常大剂量、扩展大剂量、向导算完后都可进入） |
| 覆盖方式 | 按单位或按克数直接改总量 |
| 覆盖后 | 回到主 Bolus 界面继续输注；**IOB 仍生效**（下一次计算照常扣） |

### 2.4 §7.4 By Units（p.86）

- 只输入单位数，不经过向导；适合已知剂量。
- 与「直接输入」同义。

### 2.5 §7.5 By Grams（p.86–87）

- 输入碳水克数 → 走向导计算（需要 BG / ICR / ISF / 目标 / IOB）。
- 支持多次加碳水（逐个累加）；每次都可查看计算明细。

### 2.6 泵上操作顺序（Tandem，p.81–87）

1. 主界面 → Bolus → 选「Correction Bolus / 校正大剂量」。
2. 输入或确认 BG（CGM 可自动带出；可改）。
3. 输入碳水（克数）或直接进入下一步（仅校正）。
4. 泵计算 → 显示总剂量（可 View Calculation 查看计算过程；手册未说明分项字段，也无公式）。
5. 若 BG 高于 / 低于目标，出现 Above/Below 确认页（说明为何被调整）。
6. 可 Override（按单位或克数）改总量。
7. 设定扩展比例 / 时长（可选）→ 输注。

### 2.7 参数与范围（Tandem §5.2–5.3，p.54–57）

| 参数 | 范围 | 增量 | 备注 |
|---|---|---|---|
| Correction Factor（ISF） | 1:1 – 1:600 mg/dL/U | 1 | 1 U 降低的 mg/dL |
| Carb Ratio（ICR） | 1:1 – 1:300 g/U | <1:10 时 0.1 g；≥1:10 时 1 g | 1 U 覆盖的碳水克数 |
| Target BG | 70 – 250 mg/dL | 1 | **单值**（不是高低双目标） |
| Insulin Duration | 2 – 8 h，默认 5 h | — | CIQ 开启时**固定 5 h，不可改**（p.54–55） |
| Carbs | 开 / 关 | — | 关时无「按克数」 |

### 2.8 CIQ 开启时的差异（Tandem p.55、57、80）

- Insulin Duration **固定 5 h**；主界面不显示作用时间。
- Target BG **默认 110 mg/dL**（CIQ 打开后默认值）。
- IOB **包含所有高于/低于基础率的基础胰岛素**（不只是大剂量）。
- 手动大剂量后 **60 分钟暂停自动校正**。
- CGM 当前值可自动带出到向导 BG 框；**只看当前值，不看趋势**。
- 扩展大剂量时长 **最长 2 小时**（§7.6 p.87）；**校正部分永远计入 NOW（立即）段**（§7.6 p.88）。

## §3 公式来源与差异

### 3.1 美敦力 670G 附录公式（PDF p.381–384，逐条）

> 原文标题：`Bolus Wizard feature specifications / 大剂量向导功能规格`。原文明确：**以下公式仅在碳水单位为「克」时适用**。

**参数定义（p.381）**

| 参数 | 范围 | 增量 |
|---|---|---|
| Carb units | 克（仅克） | — |
| Insulin to carb ratio（ICR） | 1–200 g/U | 1–9.9 为 0.1 g/U；10–200 为 1 g/U |
| Insulin Sensitivity Factor（ISF） | 5–400 mg/dL | 1 mg/dL |
| BG Target | 60–250 mg/dL | 1 mg/dL |
| Active Insulin Time | 默认 4 h，范围 2–8 h | 15 min |

**公式 1：当前 BG > 高 BG 目标（p.382）**

```text
食物估计 = 碳水克数 ÷ 碳水系数（ICR）
校正估计 = (当前 BG − 高 BG 目标) ÷ 胰岛素敏感系数（ISF） − 活性胰岛素
总大剂量 = 食物估计 + 校正估计
```

补充（p.382 原文）：**若「校正估计 − 活性胰岛素」为负（<0），总量只按食物估计**。

**公式 2：当前 BG < 低 BG 目标（p.382–383）**

```text
总大剂量 = 碳水克数 ÷ 碳水系数
         + (当前 BG − 低 BG 目标) ÷ 胰岛素敏感系数
         − 活性胰岛素
```

> **原文自相矛盾**：p.382 的公式含 `− 活性胰岛素`，但 p.383 的脚注写「当前 BG 低于低 BG 目标时，大剂量向导计算中**不考虑活性胰岛素**」。实现时需选定一种并实测。

**公式 3：当前 BG 在目标范围内（p.383）**

```text
总大剂量 = 碳水克数 ÷ 碳水系数
```

**公式 4：未输入 BG（p.383）**

```text
总大剂量 = 碳水克数 ÷ 碳水系数
```

**其它规则（p.384）**

- 双波大剂量若因 Max Bolus 或用户修改而小于估计值：**先减方波（Square）部分**。
- 活性胰岛素按 Active Insulin Time 记录；曲线改编自 Mudaliar 等（Diabetes Care, 1999, 22(9):1501），**只有曲线图，没有逐点公式**。

## §4 不可直接照搬的美敦力专有部分

1. **高低双目标**：Medtronic 用 Low/High BG Target 两个值决定正/负校正；Tandem 只有一个 Target BG。照搬会多出一个我们泵上不存在、也无法下发的参数。
2. **活性胰岛素时间曲线**：Mudaliar 曲线是美敦力的 IOB 模型；Tandem 用自己的 IOB 计算（CIQ 下还包含基础胰岛素）。**不能**用美敦力曲线在本地算 IOB 再与泵的 IOB 混用。
3. **0.025 U 网格与 Max Bolus 语义**：670G 的步进可配 0.025/0.05/0.1；Tandem X2/Mobi 是 0.05（Mobi 待核实）。取整必须按**当前型号步进**，不能照抄 0.025。
4. **参数范围**：Medtronic 的 ISF 5–400、ICR 1–200、BG 60–250 与 Tandem 的 1:600 / 1:300 / 70–250 不同；校验按 Tandem（或直接以泵下发值为准，不二次校验）。
5. **「低于低目标不考虑 IOB」**：与 Tandem §7.2 相反；按 Tandem。
6. **碳水单位**：Medtronic 公式只适用「克」；Tandem 允许「单位」。v2 向导只做克，单位输入继续走直接输入。

**建议**：只借「四情形分支 + 食物/校正/IOB 三段式」的结构，所有参数、阈值、取整、IOB 来源都以 Tandem 与我们现有实现为准。

## §5 与本项目现状对照

### 5.1 上游 `BolusWindow` 的血糖框与 `BolusParameters.glucoseMgdl`

事实（代码）：

- `BolusWindow` 的血糖框是**向导的 BG 输入**，不是校准：
  - 手输 → `glucoseMgdl`；
  - 自动带出 → 取自 `bolusCalculatorBuilder.value?.glucoseMgdl`（其来源是 `BolusCalcLastBG`：用户刚输入的 BG，或泵里最近的 BG 值）。
  - 提交时走 `RemoteBgEntryRequest(bgValue, useForCgmCalibration = false, autopopBg, ...)`——**明确不是 CGM 校准**。
- 上游用 `BolusParameters(units, carbsGrams, glucoseMgdl)` 把三项一起交给 `InitiateBolusRequest`，泵端据此记录食物/校正/IOB 拆分。
- **可复用性**：语义正确（向导 BG），可继续作为「BG 输入」使用；但它绑定旧 UI 与旧计算链，v2 建议**只复用字段语义与 `BolusCalcLastBG` 的取数思路**，不直接复用整个 `BolusWindow`。
- **已知疑似 bug，不要照抄**：上游计算 `autopopBg` 时用了 `bgValue != dataSnapshot.correctionFactor → false`（拿血糖值和校正系数比较）。这几乎恒为 false，疑似字段误用。v2 不复刻该判定。

### 5.2 泵到底能给什么（pumpx2 1.9.0 已核实）

| 参数 | 报文 / 字段 | 结论 |
|---|---|---|
| ICR（碳水比） | `BolusCalcDataSnapshotResponse.carbRatio`（48） | **能给**（g/U，整数域；具体缩放待实测） |
| ISF（敏感系数） | `BolusCalcDataSnapshotResponse.isf`（48） | **能给**；另有 `correctionFactor` 字段，语义与缩放**待核实** |
| 目标血糖 | `BolusCalcDataSnapshotResponse.targetBg`（48） | **能给**（当前生效值） |
| IOB | `BolusCalcDataSnapshotResponse.iob`（48） | **能给**（含 CIQ 基础量，泵自己算） |
| 最大大剂量 / 每小时上限 | `maxBolusAmount` / `maxBolusHourlyTotal`（48） | **能给** |
| 碳水开关 | `carbEntryEnabled`（48） | **能给** |
| 胰岛素作用时间 | **48 里没有**；`IDPSettingsResponse.insulinDuration` 有 | **需额外请求**；CIQ 下固定 5 h，可本地兜底 |
| 分段 ICR / ISF / 目标 | `IDPSegmentResponse` 有 | 可选；若用 48 的「当前生效值」就不需要自己算时段 |
| 当前 CGM 血糖 | 现有 CGM 数据源（`DataStore`） | **能给**（用于 BG 框自动带出） |
| 当前 BG（指尖） | 无独立“当前值”缓存；`BolusCalcLastBG` 读泵内最近 BG | 可读，需走 48/历史 |

**结论：向导需要的四大参数（ICR / ISF / 目标 / IOB）都能从泵的 48 应答拿到；只有「作用时间」需要额外请求或本地配置。**

### 5.3 现有代码里已有的东西

- `DataStore` 已缓存：`bolusCalcDataSnapshot`（48）、`bolusCalculatorBuilder`、`bolusFinalCalcUnits`。
- 上游已向泵发 `BolusCalcDataSnapshotRequest()`，并用 `pumpx2` 的 `BolusCalculatorBuilder` 本地算过。
- **pumpx2 自带 `BolusCalculator`**（本地纯计算，不依赖泵）：
  - 食物 = 碳水 ÷ ICR（g/U）
  - 校正 = (BG − targetBg) ÷ ISF
  - IOB = −iob（作为负项）
  - 中间 `double` 结果统一 **HALF_UP 保留 2 位小数**
  - 条件分支与 Medtronic 四情形高度一致（正/负校正、IOB 超校正、无 BG 等）
- **可直接复用**：参数来源（48）+ 计算器（`BolusCalculatorBuilder`）。v2 不必从零写公式。
- **注意**：pumpx2 的 `BolusCalculator` 没有做「0.05/0.025 网格量化」，也没有 Tandem 的「70 以下 IOB 参与」细分；v2 需要在其外层包一层「Tandem 口径 + 步进量化」。

## §6 初步设计

### 6.1 与「直接输入」的关系

- **同一个出口**：向导最终只产出 `BolusDraft`（`nowMilliunits` / `laterMilliunits` / `extendedSeconds` / `BolusShape` / `BolusSource.CALC`），后续形状页、确认页、发送链路**完全复用**。
- 入口：第 1 步的「碳水计算」从只读预留改为可用；进入后是一个**计算输入页**（碳水克数、BG、来源标注、计算明细），算出总量后进入第 2 步（形状/时长），用户仍可改。
- **向导不做发送、不做上限拦截**；所有上限仍在确认页统一判断（与预设、直接输入一致）。

### 6.2 输入项、来源与默认值

| 输入/参数 | 来源优先级 | 默认值 | 用户可否改 | 备注 |
|---|---|---|---|---|
| 碳水克数 | 用户每次输入 | 空 | 是 | 0–300 g；空 = 无碳水 |
| BG（mg/dL） | ① 用户手输 ② CIQ 开启且 CGM 新鲜时自动带出 | 空 | 是 | 显示来源「手动 / CGM」；**不用趋势** |
| ICR（g/U） | ① 泵 48 `carbRatio` ② 本地配置 | 无 → 阻止向导 | 否（只读展示） | 泵值优先 |
| ISF（mg/dL/U） | ① 泵 48 `isf` ② 本地配置 | 无 → 阻止向导 | 否 | `correctionFactor` 待核实后决定用哪个 |
| Target BG | ① 泵 48 `targetBg` ② 本地配置 | 无 → 阻止向导 | 否 | 单值；CIQ 默认 110 由泵给 |
| IOB | ① 泵 48 `iob` ② 无（不本地估算） | 0 | 否 | 显示「来自泵」或「不可用」 |
| Insulin Duration | ① 泵 IDP ② 本地配置 ③ CIQ 固定 5 h | 5 h | 否 | 只影响展示与说明，v2 不本地算 IOB |
| 最大大剂量 | 泵 48 | 25 U | 否 | 仅确认页使用 |
| 碳水开关 | 泵 48 `carbEntryEnabled` | 开 | 否 | 关时向导入口置灰并说明 |

**必须本地配置的只有**：参数缺失时的兜底值、低血糖阈值（70）、CGM 新鲜度（20 min）、量化规则、向导总开关。

### 6.3 计算链（按 Tandem 语义，参考 Medtronic 公式结构）

> **精度原则**：全程用高精度（Double / 毫单位），**只在最终总量落到步进网格时量化一次**；中间不做四舍五入。这与现有 `BolusForm` / `splitByPercent` 的量化口径一致。

1. 校验：ICR > 0、ISF > 0、Target 在 70–250；否则向导不可用。
2. 食物估计（U）= carbsGrams ÷ ICR。无碳水 → 0。
3. 校正估计（U）= (BG − Target) ÷ ISF。无 BG → 0。
4. IOB（U，正数）= 泵给的值；无则 0。
5. 分支：
   - **BG > Target**：`校正部分 = max(0, 校正估计 − IOB)`；`总量 = 食物 + 校正部分`。
   - **70 ≤ BG ≤ Target**：`校正部分 = 0`；`总量 = 食物`（可选项：给用户一个「按差额减少食物」开关，见 6.5）。
   - **BG < 70**：`校正部分 = 校正估计（负）`；`总量 = 食物 + 校正估计 − IOB`；若结果 < 0 → 0。（Tandem：IOB 参与；Medtronic：不参与 → 以 Tandem 为准）
   - **无 BG**：`总量 = 食物`。
6. 量化：`totalMilliunits = roundToStep(totalU * 1000, limits.bolusIncrementMilliunits)`，HALF_UP。
7. 输出 `BolusCalcOutcome(totalMilliunits, foodMilliunits, correctionMilliunits, iobMilliunits, flags)`，供「计算明细」展示。
8. 总量为 0 或低于最小步进 → 不允许进入下一步，提示「计算为 0，请检查输入」。

### 6.4 参数配置存哪（沿用阈值配置外置体系）

在现有外置 JSON（`pump_limits.json` 体系）新增 `bolusCalculator` 段，**一条一条列**：

```json
"bolusCalculator": {
  "enabled": true,
  "carbRatioGramsPerUnit": null,      // null = 只读泵 48；数值 = 离线兜底
  "isfMgdlPerUnit": null,
  "targetBgMgdl": null,
  "insulinDurationMinutes": null,     // null = 读泵 / CIQ 固定 5h
  "lowBgThresholdMgdl": 70,
  "cgmFreshnessMinutes": 20,
  "maxCarbsGrams": 300,
  "rounding": "half_up",
  "showBreakdown": true
}
```

- **优先级**：泵 48 有值 → 用泵值；泵值缺失且配置有值 → 用配置；都无 → 向导置灰并写明缺哪一项。
- 不把 ICR/ISF/目标写死进代码；配置只作兜底与调试覆盖。
- 配置加载沿用现有 `PumpLimits` 读取路径（`assets/pump_limits.json` → 类型化对象），不新造读取机制。

### 6.5 与扩展大剂量、预设、CIQ 的交互

| 交互对象 | 结论 |
|---|---|
| **扩展大剂量** | 向导只产出总量；比例/时长仍在第 2 步设。按 Tandem §7.6：**校正部分必须落在 NOW 段**。设计：形状页显示提示「校正段已计入立即段」；用户改比例时若把校正部分挪到延后段，给出说明但不拦截（v2 不发送，先保证展示正确；发送期再定硬约束）。 |
| **预设** | 预设只存总量与形状，不存向导参数；点预设 → 直接预填，**不重跑计算器**；向导算完也可「保存为预设」（存的是结果总量）。两者都落到同一个 `BolusDraft`，不产生第二条链路。 |
| **CIQ** | 目标默认 110、作用时间固定 5h、IOB 含基础胰岛素；向导只展示「IOB 来自泵（含基础）」；手动大剂量后 60 分钟暂停自动校正的提示照 Tandem 原文显示。CIQ 开启不禁止向导。 |
| **碳水开关关闭** | 向导入口置灰，提示「泵已关闭碳水录入，请用直接输入」。 |
| **未获取到 48 快照** | 不静默用 0 当 IOB、不假装参数存在：置灰并提示「未获取到泵参数」。 |

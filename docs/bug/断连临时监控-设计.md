# 断连临时监控（一次性，用完即删）

> 状态：**临时设施**。用于定位当前这次蓝牙断连；确认修好后整套删除，形成闭环。
> 不做长期归档：不写公共目录镜像、不加密、不做 7 天滚动留存。
> 不改 BLE 库（blessed / `TandemBluetoothHandler`）、不改重连策略与退避逻辑、不记泵序列号。

## 1. 为什么做、怎么定位

上次断连等了数小时，最后因「App 无法启动」卸载重装，本地证据被清空。那是孤立事件，不值得为它建永久设施；这次改为**一次性临时监控**：只在调试页开一个开关，抓断连现场，修好后删掉。

要区分的三种情况：

| 现象 | 判据 |
|---|---|
| 射频/链路超时（正常物理断链） | `DISCONNECTED` 且 `status=CONNECTION_TIMEOUT`(0x08) |
| 写失败主动剪线（工程问题，本方案重点） | `WRITE_CUT`：非授权特征写失败 → `cancelConnection()` + 手动 `onPumpDisconnected(null)` |
| 进程/服务被杀 | 心跳断档 + `processStart` 变化 / `UNCLEAN_EXIT` / `ON_TASK_REMOVED` |
| 重连策略失效/停手 | 断开后长时间无 `CONNECT_START`，或旁采到 `ReconnectPaused` / `manual_reinit` |

关键点：**写失败剪线不等射频 supervision timeout**，所以「断开」不一定等于「离得远」；必须靠 `WRITE_CUT` 与 `HciStatus` 区分。`HciStatus` 此前只进了 Toast，现已补进日志（见 §6）。

## 3. 页面（调试页一行进入）

顶部状态卡三态（按证据判定，不是布尔默认值）：

- **链路活**：已连接且 `lastBleRx` ≤ 30s
- **链路在但没数据**：已连接但 ≥ 30s 无真实回包（假连接/静默）
- **已断开**：未连接，显示距断开时长、`HciStatus`、断法来源
- `NO_LINK` / `OFF`：本进程未连过 / 采集未开启

其余项：进程 pid 与存活时长、会话 id、最近断开（status+来源）、`lastBleRxAgo`/`lastBleTxAgo`、心跳间隔、FGS 是否在跑、屏幕/Doze/省电/电池白名单/电量、深睡累计（`elapsedRealtime - uptimeMillis`）、最近一分钟 rx/tx、按来源拆分（`bolusPoll1s`/`actions1s`/`historylog`/`bulk`/`other`）、近 10 秒 bolus 轮询次数（≈并行循环数）、写失败计数（按 uuid）、incident 份数与 live 字节数。

按钮：采集开关、冻结当前、复制摘要。页面 1Hz 刷新，**只读内存，不触发写盘**。

## 4. 落盘

目录 `filesDir/diag/`：

- `live.jsonl`：常规流水，写满 **1MB 覆写重来**（不保留 prev，不报错、不停止采集）
- `incident-<yyyyMMdd-HHmmss>.json`：断连现场快照，最多 10 份，超出**删除最旧**后继续写
- `last_state.json`：原子替换（tmp + rename），30s 或关键事件后更新，带 `clean` 标记

写盘时机：

- GATT 回调线程只做**内存 append**（ring 上限 2000 条 + 计数器），绝不 IO
- 常规 15s 合并 flush（单线程 `diag-store`，有界队列）
- 关键事件立即入队并触发 flush：`DISCONNECTED` / `WRITE_CUT` / `CONNECT_FAILED` / `PAUSED` / `AWAIT_USER` / `ON_TASK_REMOVED` / `SERVICE_DESTROY` / `APP_EXIT` / `UNCLEAN_EXIT` / `SESSION_OPEN`
- incident 冻结有 20s 去抖（手动冻结不受限），避免一次断连写一堆文件
- 心跳 60s 一条；`onTaskRemoved → Runtime.exit(0)` 前**同步落盘**（`flushSync` + clean 状态），避免最后几条丢队列
- 不做 1s 落盘、不做常规 fsync；单条事件落盘最坏丢 15s，断连现场已单独冻结成文件

## 5. 取回（只做 HTTP，不做导出页）

复用现有 `HttpDebugApiService`（端口 `18282`，Basic auth，与 `192.168.8.52` 同一套）：

- `GET /api/diag/state` → 与页面同款摘要 JSON
- `GET /api/diag/files` → 目录路径 + incident 列表 + live 字节数
- `GET /api/diag/incident/latest`（或 `?name=incident-...json`）→ 原始快照
- `GET /api/diag/live?tail=500` → 常规流水末尾

注意：HTTP 只在采集开启且进程存活时可用。进程被 `Runtime.exit(0)` 杀掉后，文件仍在 `filesDir/diag/`，重新打开 App 或 `adb pull` 可拿。

## 6. 字段与判读

每条事件（JSONL）：`t`（wall 格式化）、`wall`、`el`（elapsedRealtime）、`kind`、`src`、`detail`、以及可选 `statusCode`/`uuid`/`messageClass` 等。

会话头 `SESSION_OPEN` 带：`device`、`sdk`、`processStartWallMs`、`processStartElapsedMs`、`bootCount`。

时间基的意义：

- `elapsedRealtime` 单调，跨进程重启也连续（除非重启手机）
- `processStartElapsedMs` 变化 = **进程重启**，不是断连
- `elapsed - uptime` = 深睡累计，判断是否被冻结
- `bootCount` 变化 = 手机重启

判读规则：

| 日志特征 | 结论 |
|---|---|
| `DISCONNECTED` + `statusCode=8`（CONNECTION_TIMEOUT） | 射频/链路超时（离得远）——正常物理断链 |
| `WRITE_CUT` 紧邻 `DISCONNECTED`（`status=null`） | 写失败主动剪线——工程问题，不是射频 |
| `DISCONNECTED` + `statusCode=0x13`（REMOTE_USER） | 泵侧/对端主动断开 |
| 心跳连续、`processStart` 不变 | 进程一直活着 → 排除「被杀」 |
| 心跳断档 + `processStart` 变 / `UNCLEAN_EXIT` | 进程被杀/崩溃/重启 |
| 断档 + 屏灭 + Doze + 省电，且 `uptime` 远小于 `elapsed` | 被系统冻结，定时器被推迟 |
| `PAUSED` / 旁采 `ReconnectPaused` / `manual_reinit` 后无 `CONNECT_START` | 重连策略停手 |
| 断开后无 `CONNECT_START`、`attemptCount` 推断停滞 | 重连未启动（pending connection 丢失） |
| 已连接但 `lastBleRxAgo` 持续增长、无 `DISCONNECTED` | 回调缺失/链路静默（只记录，不改库） |

已知局限：**重连尝试次数与退避发生在 pumpx2 内部，项目侧没有回调可直接观测**。方案用两个替代：连接/断开时间戳反推，以及 `DebugTree` 关键字旁采（`reconnect` / `backoff` / `ReconnectPaused` / `manual_reinit` / `await_user` / `onConnectionFailed` / `INITIAL_AUTH_NO_REPLY` / `cancelConnection` / `CONNECTION_TIMEOUT` / `CONNECTION_FAILED` / `resetInstance` / `getInstance`）。旁采是文本匹配，pumpx2 改文案会失效，属可接受的临时折中。
